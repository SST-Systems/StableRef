# Newtonsoft.Json Converter

[English](README.md) | **Русский**

Этот семпл — конвертер Newtonsoft.Json для полей StableRef. С ним поле `StableRef<T>` / `StableRefList<T>` читает и
пишет **ровно тот же JSON, что и то же поле, объявленное как голый `T` / `List<T>`**: перевод поля на StableRef не
меняет JSON, поэтому ремоут-конфиги, сохранения и данные с сервера продолжают работать.

Без него Newtonsoft видит `StableRef<T>` как обычный класс: пишет собственные поля обёртки (`TypeId` и `Value`, в
редакторе ещё `ValuesData`, `ObjectRefs` и остальной снапшот) вместо значения, а значение, записанное для голого поля,
при чтении теряет. Стабильный ID и снапшот — метаданные редактора, в JSON им не место.

Он поставляется семплом, а не частью пакета, поэтому сам StableRef от Newtonsoft не зависит.

## Что внутри

- `StableRefJsonConverter` (неймспейс `SST.StableRef.Json`) — сам конвертер; обрабатывает любые `StableRef<T>` и `StableRefList<T>`.
- `SST.StableRef.Newtonsoft` — runtime-сборка, в которой он лежит (все платформы, auto-referenced); ссылается на `Newtonsoft.Json.dll` по имени.
- `Tests/` — EditMode-тесты (`SST.StableRef.Newtonsoft.Tests`): совпадение JSON с голыми полями, `TypeNameHandling.Auto`, конвертеры для `T`, `Populate`, работа со списками, стабильные ID, `null`, JSON, записанный без конвертера.

## Подключение

1. В проекте нужен Newtonsoft.Json: пакет `com.unity.nuget.newtonsoft-json` или любая `Newtonsoft.Json.dll` (например, пришедшая вместе с каким-нибудь SDK). Без неё импортированный семпл не скомпилируется — установи Newtonsoft или удали папку семпла.
2. Импортируй семпл: **Window → Package Manager → StableRef → Samples → Newtonsoft.Json Converter → Import**. Он копируется в `Assets/Samples/StableRef/<version>/Newtonsoft.Json Converter/`. Если StableRef установлен копированием в `Assets/`, скопируй вместо этого папку `Samples~/NewtonsoftJson` из репозитория. Копия сама не обновляется — после обновления StableRef импортируй семпл заново.
3. Зарегистрируй конвертер там, где собираются настройки сериализатора:

```csharp
using SST.StableRef.Json;

var settings = new JsonSerializerSettings { TypeNameHandling = TypeNameHandling.Auto };
settings.Converters.Add(new StableRefJsonConverter());

// { "effect": { "$type": "...", "Damage": 7 }, "Effects": [ ... ] } — как для IEffect / List<IEffect>
var json = JsonConvert.SerializeObject(config, settings);
```

Для полей, которые раньше были `T[]`, создавай его как `new StableRefJsonConverter(replaceLists: true)` — см. [Чтение списка](#чтение-списка).

Чтобы запустить тесты, открой **Window → General → Test Runner → EditMode** и запусти `SST.StableRef.Newtonsoft.Tests`.

## Как это работает

### Запись

Пишется только значение — через *твой* сериализатор, с `T` в качестве объявленного типа, поэтому всё ведёт себя ровно
как у голого поля: `TypeNameHandling.Auto` добавляет `$type`, когда реальный тип отличается от `T`, используются
конвертеры, зарегистрированные для `T`, а пустая обёртка пишется как `null`. Список пишется JSON-массивом своих
значений. Стабильный ID и снапшот не пишутся никогда.

### Чтение поля

- `null` очищает обёртку. В отличие от голого поля, экземпляр обёртки в поле остаётся, поэтому код, который его читает, никогда не встретит `null`.
- Всё остальное читается так, как Newtonsoft читает голое поле `T`: конвертер заполняет член `Value` временной обёртки, поэтому `$type`, конвертеры для `T` и переиспользование существующего экземпляра значения (`Populate`, `ObjectCreationHandling`) работают ровно как для голого поля.
- Результат присваивается через `BoxedValue` с семантикой `StableRef<T>.Set`: значение того же типа сохраняет стабильный ID и снапшот записи, значение другого типа их сбрасывает.

### Чтение списка

- `null` очищает список; экземпляр в поле остаётся.
- Каждый элемент массива читается как `T`, поэтому `$type` и конвертеры для `T` работают.
- В существующий список элементы дописываются, как в `List<T>`, если только `ObjectCreationHandling` не `Replace` и конвертер не создан с `replaceLists: true` — тогда содержимое заменяется. При замене записи переиспользуются по индексу (`SetBoxedValues`), поэтому элементы, не сменившие тип, сохраняют стабильные ID.
- `replaceLists` нужен для полей, которые раньше были `T[]`: массивы Newtonsoft всегда заменяет целиком, поэтому `Populate` в существующий объект их элементы не дублировал, а с семантикой `List<T>` они бы дописались и задублировались.

### JSON, записанный без конвертера

Данные, записанные до подключения конвертера, остаются читаемыми. Объект, в котором есть и `TypeId`, и `Value` и нет
других полей, кроме полей обёртки (`TypeDisplayName`, `ObjectRefs`, `ObjectRefPaths`, `ValuesData`, `$type`, `$id`),
считается обёрткой, и из него берётся `Value`. Это покрывает JSON, записанный в редакторе (все поля обёртки), в билде
(только `TypeId` и `Value`), и списки 3.x, записанные массивом обёрток. Тип значения, у которого единственные поля
случайно называются `TypeId` и `Value`, будет принят за обёртку.

## Ограничения

- Настройки на самом поле-обёртке (`[JsonProperty(TypeNameHandling = ...)]`, `ItemTypeNameHandling`, `ItemConverterType`) до конвертера не доходят и не применяются — задавай их в `JsonSerializerSettings` или на базовом типе.
- Код не может снять снапшот для восстановления, а для значения нового типа — и проставить стабильный ID: это делает инспектор, когда рисует поле. После десериализации в ассеты в редакторе вызывай `StableRefResync.ResyncObject(asset)` перед сохранением или запусти **Tools → StableRef → Resync All** — см. [Рефлексия и сериализаторы](../../README.ru.md#рефлексия-и-сериализаторы).
