# SerializeReference Migration

[English](README.md) | **Русский**

Этот семпл переводит проект с обычных `[SerializeReference]`-полей на StableRef — и код, и сохранённые данные —
одной кнопкой. Он переписывает объявления полей в скриптах, ждёт компиляции, переносит данные всех ассетов в новую
разметку, переписывает override'ы префабов и проставляет каждой записи стабильный ID и снапшот.

```csharp
// было
[SerializeReference, Tooltip("On hit")] public IEffect effect = new Burn();
[SerializeReference] private List<IEffect> _effects = new();

// стало
[Tooltip("On hit")] public StableRef<IEffect> effect = new(new Burn());
[SerializeField] private StableRefList<IEffect> _effects = new();
```

Меняется только тип: поле сохраняет имя, модификаторы доступа и остальные атрибуты, поэтому его данные остаются под
тем же ключом. Одиночная ссылка становится `StableRef<T>`, массив или список — `StableRefList<T>` (это `IList<T>`).
Код, который читает значение, теперь обращается через `.Value` (`effect.Value.Apply()`, `effect.Set(new Burn())`):
миграция добавляет его там, где компилятор сообщает об ошибке, и там, где код скомпилировался бы, но проверял бы обёртку
вместо значения (`effect != null`); что исправить не удалось, попадает в список, а данные ждут, пока скрипты
скомпилируются.

Зачем нужен инструмент: Unity не умеет прочитать старые данные в новое поле. Поле загружается пустым, старые записи
ссылок остаются только в файле и выбрасываются при первом же сохранении ассета. Поэтому миграция работает с самими
файлами — до того, как их кто-то сохранит.

Он поставляется семплом, а не частью пакета: нужен один раз на проект, на время перехода.

> **Это помощник для миграции, а не гарантия.** Код, который использует поля, исправляется как текст, по правилам:
> `.Value` может потеряться или встать не туда, и часть таких мест всё равно компилируется — проверка вроде
> `effect != null` молча проверяет обёртку вместо значения, и игра ведёт себя иначе без всяких ошибок. Перед
> коммитом просмотри в системе контроля версий каждый изменённый скрипт, разбери предупреждения в консоли и проверь игру.

## Что внутри

- `SerializeReferenceMigrator` (namespace `SST.StableRef.Migration`) — меню и публичный API (`Analyze`, `Migrate`, `Run`).
- `MigrationCodeRewriter` — меняет тип в объявлениях, добавляет `SST.StableRef` в assembly definition и `[RefTypeId]` типам значений без стабильного ID.
- `MigrationUsageFixer` — исправляет код, использующий переделанные поля, как текст: по сообщениям компилятора, и места, которые компилятор пропускает, но которые теперь проверяют обёртку.
- `MigrationContinuation` — переносит данные после того, как переписанные скрипты скомпилировались.
- `MigrationScenes` — закрывает и открывает обратно открытые сцены, делает Resync сконвертированных.
- `MigrationYamlConverter`, `MigrationAssetIndex`, `MigrationFieldModel` — текстовая переделка одного файла ассета, типы, прочитанные из YAML, поля, которые являются StableRef.
- `SST.StableRef.Migration.Editor` — editor-сборка, в которой они лежат.
- `Tests/` — EditMode-тесты (`SST.StableRef.Migration.Tests`, тестовые типы в `SST.StableRef.Migration.TestTypes`): переделка объявлений, исправление мест использования, все виды полей в ассетах, пробный прогон, варианты префабов, override'ы объектов внутри вложенных префабов.

## Как пользоваться

1. Закоммить или сделай бэкап проекта. Миграция переписывает скрипты и ассеты в `Assets/`.
2. Импортируй семпл: **Window → Package Manager → StableRef → Samples → SerializeReference Migration → Import**. Если StableRef установлен копированием в `Assets/`, скопируй вместо этого папку `Samples~/SerializeReferenceMigration` из репозитория.
3. **Tools → StableRef → Migrate SerializeReference Data → Analyze (Dry Run)** показывает поля, которые будут переписаны, места, которые проверяли бы обёртку и получат `.Value`, `[RefTypeId]` и ссылки сборок, которые будут добавлены, и предупреждения. Ничего не записывается.
4. **Tools → StableRef → Migrate SerializeReference Data → Migrate…** Тебе предложат сохранить изменённые сцены; на время миграции открытые сцены закрываются. В скриптах меняются типы полей, Unity перекомпилирует; код, который использует поля, исправляется по сообщениям компилятора, раунд за раундом. Как только скрипты скомпилируются, данные переносятся, каждая сконвертированная сцена открывается, проходит Resync и сохраняется, а сцены, которые были открыты, открываются обратно. Отчёт пишется в консоль.
5. **Проверь изменения перед коммитом.** Просмотри дифф каждого изменённого скрипта: каждый добавленный `.Value`, `.Set(…)`, `new(…)`, `.ToArray()` — и места использования переделанных полей, которые миграция не тронула (поищи по именам полей). Разбери предупреждения в отчёте: это места, где она не смогла решить. Потерянный или лишний `.Value` может компилироваться и проявиться только неправильным поведением во время игры.

Ошибки компиляции после переписывания — это код, который использует поля. После каждой компиляции миграция исправляет те, что может разобрать, — чтение одиночной ссылки получает `.Value`, присваивание — `.Set(value)` (`.Value =`, если значение занимает несколько строк), член инициализатора объекта — `= new(value)`, `.Length` списка становится `.Count`, список, прочитанный как массив, — `.ToArray()` — и перекомпилирует, пока скрипты не скомпилируются или раунд ничего не исправит. Каждый раунд доходит и до сборок, зависящих от исправленных (пока их зависимости не компилируются, они не компилируются тоже). Assembly definition в `Assets/`, код которого теперь касается типа StableRef без ссылки на `SST.StableRef` (`CS0012`), получает эту ссылку. Остальное выводится списком в консоль — исправь руками. До тех пор остаются загруженными старые типы и данные читаются; перенос данных запустится сам после следующей успешной компиляции, когда загружены переписанные скрипты (редактор, запущенный с ошибками компиляции и *Ignore* в диалоге Safe Mode, работает на старых скриптах, и данные продолжают ждать). Поле, которое ты вернул руками, перенос не задерживает: его данные остаются как есть, и отчёт его перечисляет. **Resume Pending Migration** в том же меню запускает перенос данных сразу, **Cancel Pending Migration** прекращает ожидание.

Поля, которые ты уже вручную поменял на `StableRef<T>` / `StableRefList<T>` (с тем же именем или с `[FormerlySerializedAs]`), шаг данных тоже подхватывает.

После этого семпл можно удалить.

Чтобы запустить тесты, открой **Window → General → Test Runner → EditMode** и запусти `SST.StableRef.Migration.Tests`.

## Что он делает

### Код

- У каждого `[SerializeReference]`-поля, объявленного в скрипте внутри `Assets/`, меняется тип на месте (скрипты пакетов не трогаются — их ассеты остались бы в старой раскладке): `T` → `StableRef<T>`, `T[]` / `List<T>` → `StableRefList<T>`. Имя, модификаторы доступа и остальные атрибуты сохраняются; новых полей, свойств и `[FormerlySerializedAs]` не добавляется.
- У публичного поля `[SerializeReference]` удаляется, у непубличного заменяется на `[SerializeField]` (если его ещё нет). Auto-свойства с `[field: SerializeReference]` получают `[field: SerializeField]` и сохраняют свои аксессоры. Атрибуты обычных ссылок и отрисовки массивов (`[SubclassSelector]`, `[ListDrawerSettings]`…) удаляются. Инициализатор оборачивается (`= new Burn()` → `= new(new Burn())`). Поле без инициализатора в обычном классе получает `= new()` — иначе у объекта, созданного через `new`, обёртка была бы null и `.Value` падал бы; у компонентов, ScriptableObject (обёртку создаёт Unity) и struct (в C# 9 у них нет инициализаторов полей) его нет.
- В assembly definition изменённых скриптов добавляется `SST.StableRef`, в сами скрипты — `using SST.StableRef;`.
- Места использования, которые скомпилировались бы, но теперь проверяют или читают обёртку, получают `.Value` ещё до первой компиляции: `effect != null`, `null == effect`, `effect is null` / `is { }` / `is Burn`, `effect as Burn`, `effect = null`, `ReferenceEquals(effect, …)`, `effect.GetType()`, `effect.Equals(…)`, `effect.GetHashCode()`, `effect == other` / `other != effect`, `effect ?? other`, `effect switch { … }`, `switch (effect)`, передача `effect` в параметр типа `object` или параметр-тип (`Inject(object)`, `Open(type, object payload)`, `Foo<T>(T value)`, конструкторы тоже), а также `effect.Value` / `effect.HasValue`, если у типа значения есть член с таким именем, — `effect.Value` теперь было бы значением обёртки, а не собственным `Value` значения (становится `effect.Value.Value`). То же — для локальной переменной, в которую положили обёртку (`var r = o.effect; if (r == null)`).
- Место меняется, только если имя точно означает поле. Локальная переменная или параметр с тем же именем закрывают поле только в своей области видимости (метод, блок, лямбда, `foreach`). Тип того, что стоит перед именем (`x` в `x.effect`, объемлющий класс для `effect` / `this.effect`), читается из кода и проверяется по загруженным (ещё старым) типам: объявление (`Owner x`, параметр, `out Owner x`, `is Owner x`), `var x = …` (цепочка, `new`, `as`, приведение), элемент `foreach`, деконструкция (`var (a, b) = …`, кортежи, `KeyValuePair`, `Deconstruct`), параметр лямбды LINQ (`Where(x => …)`, `Any`, `First`, `Aggregate`…), члены и вызовы по цепочке (включая базовые классы, generic-базы вроде `Data` из `Processor<TData>`, `OfType<T>()`, индексаторы), статические типы. Поле считается переделанным, только если этот тип (или его база) его объявляет, — одноимённые поля других типов не трогаются. Где тип прочитать не удалось, работает прежнее правило: `effect` / `this.effect` в скриптах объявляющего класса, `x.effect` — если ни у какого другого типа нет поля или свойства с таким именем; остальные такие места выводятся предупреждениями (как и вызовы, параметр которых не удалось найти). Списки не трогаются: `StableRefList<T>` никогда не null, а именно от этого такие проверки и защищали; одиночное поле с тем же именем, что у списка в другом типе, различается по типу.
- Перечисляются assembly definition, которые ссылаются на сборку с типами StableRef в публичном API — пакета или сборки с переделанными публичными полями, — но не на `SST.StableRef`: код там, использующий такие члены, падает с `CS0012`.
- Типы значений без стабильного ID — классы, которые делят файл с другими и поэтому не могут взять GUID скрипта, — получают `[RefTypeId("Namespace.Type")]`. Его получают только типы, которые предложил бы селектор (конкретные классы с конструктором без параметров); для полей типа `object` ничего не добавляется — расставь вручную (попадает в отчёт).
- Не трогаются: поля с `[RefSelector]` (обычные ссылки намеренно), поля с типом generic-параметра, поля в сборках самого StableRef, объявления в несколько строк или с несколькими полями сразу (попадают в отчёт).

### Данные

Шаг данных — это текстовая переделка Unity YAML-файлов в `Assets/` (всех, кроме видов, которые никогда не хранят
данные скриптов, — материалов, анимаций, пресетов…), файл за файлом:

| Где | Было | Стало |
|---|---|---|
| поле `StableRef<T>` | `field: {rid: N}` | `field: {Value: {rid: N}}` |
| поле `StableRefList<T>` | `field: [- rid: N, …]` | `field: {_items: [- Value: {rid: N}, …]}` |
| override префаба, одиночное | `field` | `field.Value` |
| override префаба, размер списка | `field.Array.size` | `field._items.Array.size` |
| override префаба, элемент | `field.Array.data[i]` | `field._items.Array.data[i].Value` |

- Поля ищутся в основных данных компонентов и ScriptableObject, во вложенных `[Serializable]`-классах и массивах из них, а также в данных других `[SerializeReference]`-значений — StableRef-поле класса, который сам лежит по ссылке, тоже конвертируется.
- Сами записи ссылок остаются как есть, со своими ID: значения, вложенные ссылки и override'ы по `managedReferences[id]` остаются рабочими.
- Тип, которому принадлежит путь override'а, читается из YAML исходного префаба — в том числе для объектов вложенных префабов, которых в файле нет, — и из объявлений `managedReferences[id]` в самих override'ах. В старой разметке ничего не загружается.
- Ключ, сохранённый под именем из `[FormerlySerializedAs]`, переименовывается в имя поля. Пути override'ов переписываются только тогда, когда ведут к StableRef-полю: override'ы других переименованных полей остаются на Unity.
- После переделки изменённые файлы реимпортируются и проходят Resync через `StableRefResync.ResyncAssets` (исходные префабы раньше вариантов), так что стабильные ID и снапшоты записываются сразу.

### Сцены

Сцены конвертируются как любые другие файлы — поля объектов, данные их ссылок и override'ы инстансов префабов. Перед
миграцией открытые сцены закрываются (изменённые предлагается сохранить): Unity держит их в памяти в старой разметке,
а после перекомпиляции держал бы с пустыми полями, и сохранение такой сцены стёрло бы её данные. После шага данных
каждая сконвертированная сцена открывается в фоне (additive), проходит Resync, сохраняется и закрывается, а сцены,
которые были открыты, открываются обратно уже из сконвертированных файлов. Так же обрабатываются сцены, которые ты
открыл, пока правил код: после компиляции Unity держит их с пустыми полями, поэтому прямо перед шагом данных они
закрываются **без сохранения** и открываются уже сконвертированными — если в какой-то есть несохранённые изменения,
сначала будет вопрос (если их оставить, сцена не мигрируется: не сохраняй её, закрой и запусти *Migrate…* ещё раз).
Собственные инструменты StableRef сцены не открывают; миграция открывает — как разовое действие, которое ты подтверждаешь.
- Файл, уже переведённый на новую разметку, не трогается, поэтому повторный запуск ничего не меняет.

## Ограничения

- **Места использования исправляются только там, где их можно надёжно разобрать.** Оставшиеся ошибки компиляции выводятся списком в консоль: например, члены `List<T>` / массива, которых у `StableRefList<T>` нет (`Sort`, `ConvertAll`, `Array.Resize`), значение, переданное туда, где метод теперь ждёт обёртку, или многострочное значение в инициализаторе объекта. Молчаливые места (`!= null`, `is`, передача в `object`) меняются, только если имя точно означает поле; где тип получателя не читается из текста (выражение сложнее цепочки членов и вызовов, кортеж с именами элементов, метод-расширение, вызов, параметр которого не нашёлся), место выводится предупреждением — проверь их. Интерполяция `$"{effect}"` не трогается: `ToString()` у обёртки — от значения.
- **Editor-код, который ищет переделанное поле по имени** (`FindProperty("effect")`), теперь попадает в обёртку StableRef, а значение лежит в `effect.Value`; пробный прогон и отчёт перечисляют такие места.
- **Рефлексию по типу поля и кастомные drawer'ы старого поля** нужно проверить вручную: тип поля теперь — обёртка.
- **Ассеты с несохранёнными изменениями шаг данных пропускает**; отчёт их перечисляет. Из меню вместо этого предлагается выбросить несохранённые изменения в памяти.
- **При прямом вызове API** (`SerializeReferenceMigrator.Run` / `Migrate`) открытые сцены не закрываются: они пропускаются и попадают в отчёт — закрой их и запусти ещё раз. Меню их обрабатывает само.
- **Читается только текущий формат `[SerializeReference]` (версия 2, `rid:`).** Ассеты, в последний раз сохранённые Unity 2020 или старше (версия 1, ключи `id:` и `00000000:`), попадают в отчёт как нераспознанные: сначала пересохрани их в текущей Unity.
- **Бинарные ассеты не поддерживаются**: нужна *Asset Serialization: Force Text*.
- **Пресеты** (`.preset`) компонентов со сконвертированными полями не мигрируются: пересоздай их после миграции.
- **Override'ы, чей исходный префаб индекс не может прочитать** (бинарный файл, удалённый префаб), остаются как есть.
- **Editor-скрипты, которые сохраняют ассеты при загрузке**, могут сохранить ассет между перекомпиляцией и шагом данных, и его данные пропадут; сверь отчёт с системой контроля версий.
