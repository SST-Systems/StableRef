# SerializeReference Migration

[English](README.md) | **Русский**

Этот семпл переводит проект с обычных полей `[SerializeReference]` на StableRef — код и сохранённые данные — одной
кнопкой. Он переписывает объявления полей в скриптах, ждёт компиляции, а затем переносит данные всех ассетов,
префабов и сцен в новую разметку.

> **Это помощник миграции, а не гарантия.** Код, использующий поля, правится как текст, по правилам: `.Reference` может
> быть пропущен или поставлен не там, и часть таких мест всё равно скомпилируется — `effect != null` молча проверит
> обёртку вместо значения. Просмотри каждый изменённый скрипт перед коммитом, пройдись по предупреждениям в консоли и
> протестируй игру.

```csharp
// было
[SerializeReference, Tooltip("On hit")] public IEffect effect = new Burn();
[SerializeReference] private List<IEffect> _effects = new();

// стало
[Tooltip("On hit")] public StableRef<IEffect> effect = new(new Burn());
[SerializeField] private StableRefList<IEffect> _effects = new();
```

Меняется только тип: поле сохраняет имя, модификаторы доступа и остальные атрибуты, поэтому его данные остаются под
тем же ключом. Код, читающий значение, получает `.Reference` (`effect.Reference.Apply()`, `effect.Set(new Burn())`).

Зачем нужен инструмент: Unity не может прочитать старые данные в новое поле — оно загружается пустым, а старые данные
пропадают при следующем сохранении. Поэтому миграция переписывает сами файлы, пока их ничто не сохранило.

Он идёт семплом, потому что нужен один раз на проект.

## Что внутри

- `SerializeReferenceMigrator` (неймспейс `SST.StableRef.Migration`) — меню и публичный API (`Analyze`, `Migrate`, `Run`).
- `MigrationCodeRewriter`, `MigrationUsageFixer` — переписывают объявления полей и правят код, который их использует.
- `MigrationContinuation`, `MigrationScenes` — запускают перенос данных после компиляции, обрабатывают открытые сцены.
- `MigrationYamlConverter` и вспомогательные классы — конвертация данных в файлах ассетов.
- `Tests/` — EditMode-тесты (`SST.StableRef.Migration.Tests`).

## Как пользоваться

1. Закоммить проект или сделай бэкап. Миграция переписывает скрипты и ассеты в `Assets/`.
2. Импортируй семпл: **Window → Package Manager → StableRef → Samples → SerializeReference Migration → Import**.
3. **Tools → StableRef → Migrate SerializeReference Data → Analyze (Dry Run)** показывает, что изменится. Ничего не записывается.
4. **Tools → StableRef → Migrate SerializeReference Data → Migrate…** Попросит сохранить изменённые сцены. Скрипты переписываются и перекомпилируются, ошибки компиляции по возможности исправляются автоматически, затем переносятся данные. Отчёт — в консоли.
5. **Просмотри изменения перед коммитом.** Пройдись по диффу каждого изменённого скрипта и по предупреждениям в отчёте — это места, где миграция не смогла решить сама.

Если ошибки компиляции остались, исправь их вручную: перенос данных запустится сам после следующей успешной
компиляции. **Resume Pending Migration** в том же меню запускает его сразу, **Cancel Pending Migration** отменяет
ожидание.

Поля, которые ты уже перевёл на StableRef вручную, тоже подхватываются при переносе данных. Повторный запуск ничего не
меняет. После миграции семпл можно удалить.

## Что делает

### Код

- Каждое поле `[SerializeReference]` в скриптах из `Assets/` меняет тип на месте: `T` → `StableRef<T>`, `T[]` / `List<T>` → `StableRefList<T>`. Дополнительных полей и свойств не добавляется.
- У публичных полей `[SerializeReference]` удаляется, у непубличных заменяется на `[SerializeField]`. Поля получают `= new()` (или их инициализатор оборачивается), чтобы обёртка никогда не была `null`.
- Код, читающий поля, получает `.Reference` — и там, где он перестал бы компилироваться, и там, где он скомпилировался бы, но проверял бы обёртку вместо значения (`effect != null`, `effect is Burn`, `effect.GetType()`…). Запись становится `.Set(…)`.
- Использование меняется, только когда оно точно относится к переделанному полю; сомнительные места выводятся как предупреждения.
- В assembly definition добавляется ссылка на `SST.StableRef`, в скрипты — `using SST.StableRef;`, а типы значений, которые делят файл, получают `[RefTypeId]`.
- Пропускаются (и попадают в отчёт): поля с `[RefSelector]`, поля generic-параметров, объявления на несколько строк или с несколькими полями.

### Данные

Все Unity YAML-файлы в `Assets/` переписываются как текст: данные полей и override'ы префабов переносятся в разметку
StableRef, а сами объекты, на которые ссылаются поля, остаются как есть. Затем изменённые ассеты реимпортируются и
получают стабильные ID и снапшоты.

### Сцены

Открытые сцены перед миграцией закрываются (попросит сохранить) и открываются после. Каждая сконвертированная сцена
один раз открывается, синхронизируется и сохраняется. Если ты открывал сцены, пока исправлял ошибки компиляции, они
переоткрываются уже сконвертированными — при несохранённых изменениях сначала спросит.

## Ограничения

- **Не все использования полей можно исправить автоматически**, например `Sort` или `Array.Resize` на бывшем списке — оставшиеся ошибки компиляции и предупреждения перечислены в консоли.
- **Editor-код, который ищет поле по имени** (`FindProperty("effect")`), рефлексия по типу поля и свои drawer'ы старого поля требуют ручной проверки.
- **Ассеты с несохранёнными изменениями пропускаются**; отчёт их перечисляет.
- **Нужна текстовая сериализация** (*Asset Serialization: Force Text*). Ассеты, последний раз сохранённые в Unity 2020 и старше, нужно сначала пересохранить.
- **Пресеты** (`.preset`) не мигрируются — пересоздай их после.
- **При прямом вызове API** открытые сцены пропускаются — закрой их и запусти снова. Меню делает это само.
